# Implementation plan

1. **REST foundation:** Full task reads, exact project/tag resolution, sparse creation/update, task lifecycle, schedules/deadlines, task queues, and preview-first sequential bulk changes are implemented and covered by MCP tests.
2. **Priority and hierarchy:** Versioned capability discovery gates priority and parent changes. Native TaskService/conversion actions preserve app invariants; priority set/clear and assign/reparent/promote passed live MCP readback.
3. **Ordering:** move_task_in_order supports project, backlog, tag/Today, and subtasks with exact context validation. Project, Today, subtasks, and backlog passed live verification. Backlog verification used four disposable tasks, three deterministic moves, independent order readbacks, membership and metadata checks, and an invalid-anchor no-mutation check. Section ordering is unsupported because membership and ordered context arrays must change together.
4. **Historical time:** `adjust_task_time` accepts add/remove, a calendar date, and positive integer milliseconds. It flushes pending timer sync and uses native time actions/reducers to maintain daily values and totals. Live add/remove and metadata preservation passed.
5. **Project/tag administration:** manage_project creates, renames, and deletes only empty non-Inbox projects. The app's native project removal cascades tasks and notes, so this restriction prevents data loss. manage_tag creates and updates title/hex color; deletes only empty tags and protects Today. Full disposable lifecycles passed live.
6. **Classified exclusions:** Recurrence write operations remain unsupported pending one semantic workflow that preserves generated instances, scheduling cursors, exceptions, templates, reminders, and completion semantics. HTTP(S) link creation, title-only rename, and exact detach passed live verification. Local file/image writes remain unsafe, and binary transfer is unsupported. Provider issue metadata stays read-only; board membership and Today are derived.
7. **LLM workflow pass:** Existing high-level tools cover task context bundles, queues, exact resolution, duplicate-safe provider-specific ensure, ordered moves, safe bulk preview, and capability diagnostics. Generic upsert would impose hidden duplicate policy; desired-state diff is already available through sparse updates/bulk preview. Do not add another helper in this closure run.
8. **Release readiness:** Clean tarball install, stock-mode MCP handshake, full MCP verification, package dry run, and the Super Productivity full Karma suites passed. The America/Los_Angeles run passed 16,542 tests (20 skipped). The forced-dev token logging path was closed and its security tests passed. Temporary fixtures were removed and read back as absent. Keep publication and push for a separately authorized release step; neither was performed.
